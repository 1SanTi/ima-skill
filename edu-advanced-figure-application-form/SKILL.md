# 教育系统先进人物申报材料填写

## 概述

根据评选通知（内含空白表格模板与填写要求）和候选人信息（手填扫描版或口述/文本），**在原始通知文件上直接填写**，生成一套与原件格式完全一致、可直接打印提交的申报材料 Word 文档，包括：

1. **申报表**（附件3）——基本信息、工作简历、荣誉、教学工作量、先进事迹、意见栏
2. **拟推荐人选汇总表**（附件4）——一行18列的候选人汇总数据
3. **拟推荐候选人征求意见表**（附件5）——姓名/单位/职务/类别 + 各级意见栏
4. **先进事迹材料**（附件6）——标题 + 综合表现（400字内）+ 主要业绩（1600字内），第三人称

核心原则：**改内容、不动格式**。表格结构、合并单元格、边框、列宽、字体、封面下划线等一律保留原样，只在对应位置填入文字。

## 你的工作方式

### Phase 1：解析输入

1. 用 `fetch`（type=file_path）读取全部上传文件，完整提取文字。
2. 识别三类信息的对应关系：
   - **要求来源**：评选通知正文 + 附件里空白申报表与「填表说明」，确定字段结构、字数限制、格式要求。
   - **内容来源**：已填写申报表扫描件或候选人信息，这是要搬运进正式表的数据。
   - **输出对象**：需要完成的正式申报表（通常是通知里的「附件3」）。
3. 若某字段以哪份文件为准不确定，以通知正文和模板的规范表述优先。

### Phase 2：整理信息并纠错

逐字段整理候选人信息，修正扫描/手写识别错误。读取 `references/fields.md` 获取字段清单与常见修正规则。

原则：**改错不改义**——只修明显错字、单位/日期/名称规范化、字数超标压缩，不增删实质信息；拿不准时保留原样并在交付时提示用户核对。

### Phase 3：在原表上填写

用两个脚本分别生成：

**申报表**（`fill_form.py`）：
```bash
python3 scripts/fill_form.py \
  --template 原始通知.docx \
  --data 候选人信息.json \
  --out 输出申报表.docx
```

**其余三份材料**（`generate_attachments.py`，一次生成三份）：
```bash
python3 scripts/generate_attachments.py \
  --template 原始通知.docx \
  --data 候选人信息.json \
  --outdir 输出目录
```

- 候选人信息以 JSON 组织，字段清单见 `references/fields.md`，示例见 `assets/candidate_template.json`。
- 不传 `--data` 时使用脚本内置示例数据（结构参考）。
- 两个脚本都按位置填写，依赖原表结构稳定；若通知模板结构变化，先读 `references/fields.md` 了解对应关系再调整。

### Phase 4：校验交付

生成后用 `fetch` 读回每份 docx，逐项核对：申报表（封面、基本信息、简历、荣誉、教学工作量、事迹）、汇总表（18列）、征求意见表（姓名/单位/职务/类别）、事迹材料（标题+两部分）。确认无误后用 `provide_file` 逐份给下载链接，并列出已做的修正项供用户复核。

## 脚本说明

- `scripts/fill_form.py`：生成申报表（附件3）。基于 python-docx，直接操作原 docx 元素——删除非申报表段落/表格、在封面下划线 run 与表格单元格中写入文字。
- `scripts/generate_attachments.py`：生成汇总表（附件4）、征求意见表（附件5）、先进事迹材料（附件6）三份文件。
- 依赖：`python-docx`（环境已预装）。
- 输入 `--template` 为含全部附件的原始通知 docx；输出为独立 docx。
- 两个脚本内部都做了中文输出路径的兼容处理（先存英文临时文件再重命名）。

## 字段与修正规范

字段清单、填写要求和常见扫描错误修正规则，见 `references/fields.md`。整理候选人信息前先读该文件。

## 工作流示例

**示例 1：从扫描版申报表生成正式表**
用户上传「评选通知」+「手填扫描版申报表」。读取两份文件 → 从通知确认字段结构和全称规范 → 从扫描表提取候选人信息并修正错字（如"遵源中学→蓬源中学"）→ 整理成 JSON → 运行 `fill_form.py`（template 指向通知）→ 读回校验 → 提供下载。

**示例 2：口头提供信息生成申报表**
用户说"帮我填一份优秀教师申报表，名字是张三，单位是……"。按 `references/fields.md` 逐字段补齐缺失项（通常只追问一次，列出缺的字段）→ 整理成 JSON → 运行脚本 → 交付。

## 注意事项

- 申报表涉及真实人事信息，交付前务必读回校验，不要直接信任脚本输出。
- 涉及姓名、身份证号、荣誉、电话等敏感信息，仅在用户明确要求生成申报表时写入，不额外扩散。
- 事迹材料若需压缩字数，遵守通知规定上限（通常 500 字内、第三人称），保留核心事实。
- 若通知模板与本脚本假定的结构不一致，先检查再填，必要时调整脚本中的表格/行定位。
