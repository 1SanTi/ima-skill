# 先进人物申报材料修改与归档

## 概述

用户常给出一套已填好的申报材料（多个 .docx）和一段口述修改要求（录音或文字），要求按新要求修改后归档。本技能提供标准流程：**在原表上就地修改、保持原格式、逐项核对、分类归档**。

核心红线（用户通常会特别强调）：**只在原文件、原表格上修改内容，不重建表格、不重新排版**。因此所有改动都通过文本替换、单元格改写、删除表格行完成，字体/边框/合并单元格/列宽保持原样。

## 你的工作方式

### Phase 1：解析修改要求

1. 若要求来自录音，先用 `fetch`（音频 native 解析）或 `speech-to-text` 技能转写为文字。
2. 把转写内容逐条整理成**待改点清单**：每条注明"哪个文件 / 改什么 / 怎么改"。转写常有口语重复和错别字，要结合材料原文本判断真实意图。
3. 识别"基准变化"：用户往往是把整套材料从一个申报类别/年份改为另一个（例如「2026年·优秀班主任」→「2024年9月·优秀乡村教师」）。据此推导连带修改：
   - **申报类别名称**：所有"申报/推荐/类别/标题"处的名称统一替换。
   - **时间**：封面、落款、公示、鉴定意见等处日期整体平移。
   - **年限倒推**：站在新时间点，教龄、班主任年限、乡村工作年限等按年差相应减少（如整体回退 2 年则 31→29、14→12）。
   - **删除超期内容**：新时间点之后尚未发生/尚未获得的荣誉与事迹（"某年及以后"）全部删除。
   - **删除超期表格行**：如工作量表中晚于新时间点的学年行。
4. **区分"申报类别"与"历史荣誉"**：只替换申报类别名称；候选人历史上获得的其他称号（如曾获"县优秀班主任"）是事实，不得篡改。判断依据：出现在"申报奖励名称/推荐类别/标题"处 → 改；出现在"荣誉/获奖"列表 → 保留。

### Phase 2：定位文件与精确修改点

1. 列出所有待改 .docx，逐个用 `scripts/docx_inplace.py <file>` 或 python-docx 查看段落数、表格数、行列数。
2. 对每个文件扫描关键词（旧类别名、旧年份、待改数字等），输出"命中位置清单"（段落文本 / 表格 cell 文本），确保不遗漏、不误伤。
3. 注意常见坑：合并单元格导致 `row.cells` 重复（用 `lc(row)` 去重后按逻辑列定位）；同一文本在多个位置出现（须按上下文精确定位）。

### Phase 3：在原表上修改

用 `scripts/docx_inplace.py` 提供的函数编写修改脚本：

- `rep(p, old, new)`：段内替换，先逐 run 再整段兜底，**保留原格式**。
- `rep_all(doc, old, new)`：全文档（含表格单元格）替换，适合类别名/日期这类全局替换。
- `rep_cell(cell, ...)` / `lc(row)`：按逻辑单元格精确改写（如教龄、年限）。
- `del_row(row)`：删除整行（如超期工作量行、超期荣誉行）。
- `save_doc(doc, out)`：保存，**内含中文路径兼容处理**（先存英文临时文件再重命名），避免中文名 docx 写坏。

编写要点见 `references/edit-patterns.md`（含典型改法、跨 run 陷阱、中文路径陷阱、年限倒推算法）。

### Phase 4：逐项对照核对

修改完成后，**读回每份文件**（fetch 或 python 打印），对照 Phase 1 的待改点清单逐条核实：
- 该改的是否都改了（类别名、日期、年限、删除项）；
- 不该改的是否被误改（历史荣誉、固定事实如出生日期/参加工作时间）；
- 删除行后表格结构是否正常。

发现问题立即修正（脚本每次从原件重新复制，可安全重跑）。

### Phase 5：分类归档到知识库

1. `search_knowledge_base` 确认目标知识库及其 `role_type`（须有写权限）。
2. `create_folder` 在知识库中新建文件夹（如「XXX-优秀乡村教师申报材料」），记录返回的 `folder_id`。
3. 用 `upload-to-kb` 技能的 `upload_to_kb.py --folder-id <folder_id>` 逐份上传。
4. `get_knowledge_list` 复核文件夹内容，向用户报告。

## 资源

- `scripts/docx_inplace.py` — 就地修改工具库（导入使用，也可命令行查看文档结构）。
- `references/edit-patterns.md` — 典型修改模式、年限倒推方法、技术与意图两类陷阱。

## 注意事项

- 涉及真实人事信息，修改后必须读回核对；不臆造未提供的内容。
- 知识库写入不可逆（无删除 API），上传前确认文件夹与文件无误。
- 若修改要求含糊（如"往前面推"未说明幅度），结合上下文推导并在交付时说明推导依据，供用户复核。
