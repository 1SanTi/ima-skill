# 链接转二维码

把一段链接或文本变成一张可直接扫码的 PNG 图片。默认走"高纠错 + 中文标注 + 自动校验 + 交付下载链接"的完整链路，产出物是用户能直接保存转发的一张图。

## 为什么这样做

- **纠错等级必须高**：二维码常被转发、压缩、截图，H 级（容错约 30%）能让它在轻微模糊、脏污、甚至中心嵌 logo 的情况下依然可扫。低等级只在极端追求码点密度时才用。
- **必须回读校验**：生成脚本自己"扫"一遍再交付，能拦住文字压占码区、尺寸过小、参数写错导致的不可扫问题。没校验就交付，等于把风险丢给用户。
- **必须用 provide_file 交付**：用户看不到沙箱文件系统，本地路径对用户无意义。生成后一定调用 `provide_file` 返回下载链接，并在回复里用 Markdown 链接展示。

## 工作流

### 第 1 步：确认要编码的内容

从用户消息里取链接或文本。**链接要原样保留**（含 `https://`、查询参数、短链后缀），不要自行补全或改写，否则可能扫到错误页面。

用户没给标注文字时，按需自行拟一个简短的标题（例如「扫码打开 XX 官网」「微信扫码 · 领取 XX 算力」），并在交付时说明"文字可改/可去掉"，不要为此反复追问。

如果用户明确说要纯二维码、不带任何文字，加 `--no-text`。

### 第 2 步：生成二维码

```bash
cd /sandbox/workspace/skills/link-to-qrcode
python3 scripts/make_qrcode.py \
  --url "https://example.com/xxx" \
  --title "扫码打开 XX 官网" \
  --subtitle "一句话补充说明" \
  --box-size 24 \
  --out /sandbox/workspace/output/XX二维码.png
```

脚本会自动补齐依赖（qrcode、PIL），生成后立即用 OpenCV 回读校验，并打印结果：

```
[✔ 校验通过] /sandbox/workspace/output/XX二维码.png  888x1112  -> https://example.com/xxx
```

看到 `✔ 校验通过` 且打印的链接与输入一致，才算生成成功。

### 第 3 步：视觉复核（推荐）

带文字的图用 `fetch` 看一眼排版，确认标题没被裁切、文字没压到二维码：

```
fetch(type="file_path", id="<输出路径>", question="文字是否完整、有无裁切或与二维码重叠？整体是否居中？")
```

发现文字溢出或比例失衡，调整 `--box-size`（改整体尺寸）或缩短文字后重新生成。

### 第 4 步：交付

```
provide_file(file_path="/sandbox/workspace/output/XX二维码.png")
```

回复中用 `[📥 文件名.png](download_url)` 展示，并一句话说明用途（扫码后会发生什么）。若用户还要其他形式（去文字、换底色、加大尺寸、批量），按参数表调整即可。

## 参数速查

| 参数 | 说明 | 建议 |
|---|---|---|
| `--url` | 要编码的链接或文本 | 与 `--file` 二选一，必填 |
| `--file` | 批量文件，每行 `URL[|标题]` | 空行与 `#` 开头行自动忽略 |
| `--title` | 二维码上方标题 | 控制在全角 14 字以内更美观；脚本会自动缩字号防溢出 |
| `--subtitle` | 二维码下方灰色提示 | 一行短句，别超过约 22 字 |
| `--out` / `--outdir` | 输出路径 / 批量输出目录 | 单张建议 `/sandbox/workspace/output/` |
| `--box-size` | 单格像素，决定整体大小 | 默认 16；追求清晰可扫用 20–24 |
| `--border` | 静默边格数 | 保持 ≥2，太小会干扰识别 |
| `--ec` | 纠错等级 L/M/Q/H | 默认 H，不建议下调 |
| `--fg` `--bg` | 前景/背景色 | 保持深色码点 + 浅色底，对比度越高越好 |
| `--logo` | 中心 logo 图片路径 | 仅在 `--ec H` 下使用；脚本自动限幅到 20% |
| `--no-text` | 只出纯二维码 | 用户要裸码时用 |
| `--scale` | 整数整体放大 | 想保留原始码点大小、只放大整图时用 |
| `--no-verify` | 跳过回读校验 | 一般不用；除非环境缺 opencv 且必须出图 |

批量示例：

```bash
python3 scripts/make_qrcode.py --file links.txt --outdir /sandbox/workspace/output/qrcodes --box-size 20
```

`links.txt` 内容：

```
https://ima.qq.com/xxx|领取 ima 算力
https://dshdesktop.com/zh/|DSH Desktop 官网
# 井号开头是注释
```

## 常见问题

- **校验失败**：先加大 `--box-size`，检查 `--border` 是否 ≥2、前景/背景对比是否足够；文字压到码区也会导致失败，缩短 `--title`。
- **文字被裁切或挤在一起**：脚本按画布宽度自动收字号，若仍不理想，直接删掉 `--subtitle` 或精简标题。
- **用户要"扫了能直接下载 App"**：二维码只能承载一个网址，扫码后落在网页完成下载。若链接是邀请/活动页，说明文字里写清"扫码打开邀请页"即可，不要承诺"扫码即装"。
- **短链 vs 长链**：长链会让码点更密、更难扫。如果用户有短链，优先用短链。
