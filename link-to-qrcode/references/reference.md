# 二维码生成参考手册

## 一、尺寸与清晰度对照

二维码的物理大小 = 单格像素（`--box-size`）× 总格数（含静默边）。链接越长，二维码版本越高、格数越多，同样 `--box-size` 下整图越大、单格越小。

经验值（常见 40–80 字符链接）：

| `--box-size` | 整图宽度 | 适用场景 |
|---|---|---|
| 8 | ~300 px | 网页/电子图内嵌 |
| 16 | ~590 px | 默认，手机扫码足够 |
| 20 | ~740 px | 打印、纸质海报 |
| 24 | ~890 px | 大屏展示、远距离扫码 |

判断标准：**最小码点（单格）在最终展示尺寸下不应小于 0.5 mm**。如果二维码会被印到 A4 纸以外的位置再缩小，先按实际印刷尺寸反推，宁大勿小。

## 二、纠错与容错

| 等级 | 容错 | 何时用 |
|---|---|---|
| L | ~7% | 内容极长、必须压缩码面 |
| M | ~15% | 一般电子屏展示 |
| Q | ~25% | 中等风险环境 |
| **H** | **~30%** | **默认**：会被转发/压缩/截图，或中心要放 logo |

中心嵌入 logo 时，遮挡面积不要超过码面的 20%，且必须配 H 级纠错。脚本 `paste_logo` 已按 20% 限幅并加白底留白，避免图形边缘与码点粘连。

## 三、扫码兼容要点（微信 / 系统相机）

1. **静默边（quiet zone）不能省**：`--border` 至少 2 格。贴边裁切会导致定位角标丢失，识别率骤降。
2. **颜色对比要足**：深色码点 + 浅色底是最稳的组合。若必须反色（浅码点 + 深底），务必实机测试——部分扫码器对反色支持不稳。
3. **不要彩色渐变码点**：装饰性渐变色会增加误码率，尤其在低端摄像头下。
4. **避免中心大面积遮盖**：超过 25% 遮挡即使 H 级也可能读取失败。
5. **微信扫码会自动跳转网页**：如果目标页需要"在浏览器中打开"才能下载，说明文字里最好提示"右上角选择在浏览器打开"。

## 四、带文字标注的版式

脚本生成的版式为「上标题 / 中二维码 / 下灰色提示」三段式：

- 标题：加粗、与前景同色，起"扫码做什么"的作用，例如「微信扫码 · 领取新人算力」。
- 副标题：灰色（`#555555`），起补充说明作用，例如「扫码打开邀请页，下载安装 App」。
- 字宽上限自动压到画布宽度的 88%–90%，超长自动降字号（最小 16 px）；仍放不下时优先精简文字，而不是继续缩字号——过小反而看不清。

## 五、脚本内部机制

`scripts/make_qrcode.py` 的关键点，便于排错时定位：

- 依赖自愈：首次 import `qrcode` 失败时自动执行 `pip install "qrcode[pil]"`。沙箱会话重置后第三方库会丢失，这一步保证脚本始终能跑。
- 字体查找：按 Noto CJK → 文泉驿 → DejaVu → Windows/ macOS 字体的顺序取第一个存在的，避免中文变成方框。
- 回读校验：保存后用 OpenCV `QRCodeDetector` 解码，与输入内容逐字比较；不一致或识别不出会返回非零退出码并打印告警。缺 OpenCV 时降级为"未校验"而非报错。
- 文件名清洗：把 URL 转成安全文件名（去协议、非法字符换下划线、截断 60 字符），批量模式直接用它命名。

## 六、常见失败模式速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 校验返回"未识别出二维码" | 码点太小 / 静默边不足 / 对比度低 | 提高 `--box-size`、`--border`≥2、加深前景色 |
| 微信扫不出，系统相机能扫 | 码面被压缩或留白被裁 | 增加静默边，导出时不要贴边裁剪 |
| 中心 logo 后无法识别 | 遮挡过大或未用 H 级 | logo 缩到 20% 以内，确认 `--ec H` |
| 中文显示成方框 | 系统无中文字体 | 用 `--font` 指定字体文件 |
| 长链接码面过密 | URL 太长 | 换短链；或提高 `--box-size` 保证单格足够大 |
