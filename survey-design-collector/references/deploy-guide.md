# 部署与对外说明（公网访问）

## 核心结论（务必先跟用户讲清）

- 问卷系统默认是**本地部署**，二维码指向 **内网地址**（`192.168.x.x` / `127.0.0.1`），
  **只有连同一个 WiFi 才能打开**。老师在**外地/用流量**扫码就会"打不开——页面无法显示"。
- 要让**任意网络**的老师都能答题，必须给它一个**公网地址**。三条路（按推荐度）：

| 方案 | 适用 | 成本 | 本机需开机 | 稳定性 |
|------|------|------|-----------|--------|
| **A. 云服务器** | 正式、长期 | 约几十~一百多元/年 | 否 | 高 |
| **B. 内网穿透** | 应急、临时 | 免费额度 | 是 | 中 |
| **C. 现成问卷平台** | 极紧急、过渡 | 免费 | 否 | 高（但非自建） |

## 方案 A：云服务器（推荐）

系统已内置公网适配：**后台二维码会按当前访问的域名/IP 自动生成**，也可用 `PUBLIC_URL` 强制指定。
部署包见 `assets/app/部署到公网/`：`install.sh`（一键）、`survey.service`、`Dockerfile`、`docker-compose.yml`、
`云服务器部署指南.md`、`内网穿透快速方案.md`、`故障排查_常见问题.md`。

一句话流程：买轻量云服务器(Ubuntu) → 上传文件夹 → `bash 部署到公网/install.sh` → 安全组放行 80 → 打开 `http://公网IP/admin` 出二维码。

- 部署后若"打不开"，**99% 是安全组/防火墙没放行端口**。
- 后台密码：环境变量 `ADMIN_PWD=xxx`，访问时加 `?pwd=xxx`。
- 数据：`/opt/survey/data/responses.db`。

## 方案 B：内网穿透（最快）

本机运行系统 → 用 cpolar / 花生壳 / ngrok 把 8000 映射成公网地址 → 后台点开 `/admin`，
把「答题网址」改成穿透地址，二维码自动更新。注意本机需一直开机、免费地址可能变动。

## 方案 C：现成问卷平台（过渡/保底）

时间极紧时，可把题目录入**腾讯问卷 / 问卷星**（免费、零技术、自动统计）。
生成题目清单的方法：读取 `questions.json`，按 `sections → questions` 输出题号、题干、题型、选项
（量表题用 `scale_options`，`rating` 写 1—N 分带端口标签，`allow_other` 追加"其他（请注明）"），
另存为 `应急方案_用现成问卷平台.md`。

## 给用户的话术模板

> 老师在群里"打不开"，是因为现在这个二维码是**本地地址**，只有同一个 WiFi 能进。
> 想让全国各地的老师都能扫码答题，需要给它一个**公网网址**，有三条路：
> ① 挂到一台云服务器（最稳，推荐）；② 本机 + 内网穿透（最快，应急，电脑要开着）；③ 先用腾讯问卷/问卷星过渡。
> 我可以给你一键部署脚本和图文步骤；你只要买/开一台服务器，我带你 10 分钟搞定。

## 常见问题速查

| 现象 | 解决 |
|------|------|
| 扫码打不开（本地） | 换成公网方案（A/B/C） |
| 公网仍打不开 | 安全组/防火墙放行端口 |
| 二维码地址不对 | 后台改「答题网址」自动更新；或设 `PUBLIC_URL` |
| 选了选项却要填"其他" | 是旧版 bug，用最新版（已修复） |
| 端口被占用 | `PORT=8080 python3 server.py` |
| 想清空数据 | 删除 `data/responses.db` 重启 |
